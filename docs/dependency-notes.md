## Why the production bundle remains local-first

No runtime dependency provides authentication, analytics, maps, telemetry, a hosted database, or an AI API. The core demo loads the compiled application and five same-origin generated images. Dexie talks only to IndexedDB. The scene exporter normalizes the generated SVG's computed colors to portable sRGB and rasterizes it with browser Canvas; jsPDF creates the report document. REPLAY uses only jsPDF text, shape, and PNG APIs, so its optional `html2canvas`, `DOMPurify`, and `canvg` renderer modules are excluded from the release bundle; a build guard and API-type guard fail if that contract drifts. Exports run only after an explicit action. In Site Tools mode, the browser/client itself can pass a called tool's compact structured result to its model service; that external boundary is not a package-level runtime API and is documented separately in `PRIVACY.md`.

The initial planning-only dependencies Zustand, Immer, `webmcp-types`, and `@testing-library/user-event` have been removed from `package.json` and the lockfile. Canonical state is implemented by `ReplayEngine` plus React state, and current WebMCP declarations live in `src/webmcp/types.ts`.

Dependencies still execute with same-origin application authority, so “local-first” is not a substitute for supply-chain review. Keep versions pinned, review lockfile changes, run `npm audit` or the organization’s preferred scanner, and verify production network behavior.

## Cleanup and release checks

1. Confirm every remaining direct package is still imported by production or verification code; remove any package that becomes unused.
2. Run `npm ci` from a clean checkout and review warnings.
3. Run the complete checks in [testing.md](testing.md).
4. Regenerate and review [`THIRD_PARTY_NOTICES.md`](../THIRD_PARTY_NOTICES.md) from the exact production dependency tree whenever `package-lock.json` changes; generate a formal SBOM as well if the deployment organization requires one.
5. Review transitive licenses from the exact lockfile. The checked-in inventory improves traceability but is not a substitute for the release owner’s legal review.
6. Verify no asset or dependency introduces a third-party trademark, font, music track, or service requirement into the demo.
7. Record the final dependency tree with `npm ls --all` and investigate unexpected duplicates or invalid peer relationships.

Useful commands:

```bash
npm ls --depth=0
npm audit
npm outdated
```

`npm outdated` is informational. Do not upgrade during release solely to make the list empty; evaluate API changes, then rerun the full verification matrix.
