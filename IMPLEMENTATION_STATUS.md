## Implemented product

- React 19/Vite/strict TypeScript application with landing page, four deterministic unique-run demos, in-workspace scenario switching, blank-case wizard, stable `#case/<encoded-case-id>` resume routes, a landing-page list of retained local cases, explicit unavailable-route recovery, malformed-record recovery, a cross-tab conflict pause, a framing guard, and a recoverable root error boundary.
- Canonical `ReplayEngine` command layer with strict Zod/reference validation, exact branch ownership indexes, duplicate-free reciprocal provenance links, deterministic consistency rules, version conflicts, request idempotency, locks, human/UI-only claim confirmation, completeness attestation, and report finalization, explicit human-override correlation, activity, undo/redo, and safe agent-action reversion. Agent undo cannot restore human authority.
- `ReplayCase.schemaVersion = 2`, including a v1→v2 migration for annotation links, report workspace paths, and the proposal ledger plus a safe additive default for completeness attestations. The current deterministic fixture is `seedVersion = 6`; schema v2 accepts valid saved positive seed versions through 6. Fresh demo actions create a unique run and leave older runs intact. Schema-v2 state uses a distinct local vault while retaining legacy records for migration/recovery.
- Optional, replayable onboarding is available from the landing page and workspace: a seven-topic guide, a mutation-free six-step tour, live Site Tools readiness guidance, copyable collaboration prompts, and versioned preference-only progress. Scene/path help explains timed points, straight-line interpolation, lane snap, uncertainty markers, exact controls, and the absence of collision-physics or fault modeling.
- Compare-and-swap IndexedDB writes, strict incoming save validation, a best-effort Web Locks edit lease where supported, BroadcastChannel conflict notices, retained raw recovery records, a narrow audited local-only repair for released reciprocal-index and global-claim defects, pre-decode upload signature/container-dimension limits plus post-decode verification, stored evidence-blob case/checksum/MIME verification, a durable crash-reconciled evidence purge queue, and a cancel-first structured-transfer review that itemizes unavailable local evidence bytes and every unsigned trust reset before a re-keyed copy is opened.
- Manual scene/timeline authoring, including exact actor-pair impact placement for three- and four-vehicle cases without disturbing other contacts; provenance-aware claims with required cited images for photo/document observations; local evidence and annotation-level links with human-only reciprocal unlinking that preserves the asset; ranked questions; hypothesis branches/assumptions; human completeness review for no evidence, unknown/not-assessed actor damage, and reviewed uncertainty; report preview/review/finalization; and explicit JSON/PDF/SVG/PNG downloads.
- Reversible coordinated-scene proposals: only an agent/WebMCP call can create a preview; only a human UI action can adjust, accept, or reject it. Acceptance validates every recorded baseline and lock before applying any proposed geometry.
- Nineteen defined imperative WebMCP tools with lifecycle groups, fixed schemas/annotations, cancellation cleanup, verifiable compact result/error envelopes, visible UI coordination, and an inspector: 18 are present for the baseline workspace and `add_report_note` makes 19 while a current transient report preview exists. A successful note invalidates that preview and returns the next inventory to 18; rebuilding at the new version restores 19. `propose_scene_changes` is the coordinated-scene proposal entry point; `upsert_scene_actor` supports narrow partial updates while preserving omitted trusted specifications.
- Visible declarative `finalize_factual_report` form with no `toolautosubmit`; only the human UI can dispatch `report.finalize`. OpenAI's built-in Site Tools browser currently does not expose declarative form tools. Its ordinary browser interaction is a separate capability, not a WebMCP call or authorization to operate the human confirmation controls.
- Durable canonical activity for domain mutations plus a separate capped, session-only audit for successful/rejected read or UI-only tool invocations. A cancellation before primary persistence begins creates neither entry; a cancellation after a staged save resolves is reconciled through a compensating save before the invocation settles when compensation succeeds.
- Five active visual assets delivered as seven optimized local WebP files: three responsive renditions of one hero plus four clearly labelled synthetic demo evidence images. There is no runtime image/model API dependency.

## Known implementation limits

- Ordinary human-UI commands commit to the live engine before their queued compare-and-swap IndexedDB save; a save failure can therefore leave live memory newer than storage and pauses further mutations until a retry succeeds. The user may download an explicitly incomplete structured transfer while paused, but that download does not make the case durable or resume editing. WebMCP mutations instead reduce on an isolated engine copy, compare-and-swap save the staged case, and only then adopt/notify the live engine. A rejected primary save leaves live state untouched; cancellation or a live-version conflict after a resolved save triggers compensation, while failed compensation returns and audits `PERSISTENCE_FAILED`. These paths still do not form one physical transaction with IndexedDB or browser paint.
- Exact request receipts and undo/redo snapshots are in memory. Persisted activity records the request ID, semantic caller-intent fingerprint, original case version, activity ID, summary, and affected IDs used to prevent replay and synthesize an `idempotent: true` response after reload. The exact prior result payload is not stored in a separate durable journal.
- Web Locks availability is browser-dependent. Compare-and-swap remains the final local-write guard, and multi-tab recovery can still require a reload.
- Structured JSON is a case transfer, not a complete backup: it excludes evidence bytes and contains the source case ID. The visible import flow opens a re-keyed local copy; unsigned import intentionally demotes or clears human attestations, reviewed state, and immutable report snapshots. Imported completeness records remain visible history but do not clear readiness until a fresh local UI review. File imports and new writes reject ambiguous ownership or asymmetric provenance rather than invoking the local-vault compatibility repair.
- Malformed/unsupported local records are retained for explicit raw recovery, not made safe by that retention. The read path repairs only the deterministic released reciprocal-index/global-claim defects with one system migration activity; ambiguous duplicate trajectories and unclear ownership remain quarantined. Recovery JSON can contain sensitive or invalid content.
- Scene SVG/PNG captures the current semantic layers after removing transient selection/edit handles and resetting pan/zoom, then appends a non-overlapping review band with case version, branch, playhead, certainty/authorship cues, comparison/proposal context, and the non-simulation disclaimer. PDF uses the same labelled scene snapshot only when its preview version still matches the open case; otherwise it explicitly omits newer geometry. Long report content paginates rather than clipping, and stalled rasterization fails with a bounded timeout. Downloaded-file fidelity still requires manual inspection.
- WebMCP result completion is not transactionally coupled to browser paint. Deterministic real-adapter staging/compensation tests and separate Dexie persistence tests exist, but a combined real-adapter + actual-Dexie cancellation/storage-failure/compensation journey is still pending.
- `evals/webmcp-evals.json` is a specification, not an executable harness or evidence of supported-model runs.
